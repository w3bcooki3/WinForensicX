WinForensicX field guide

A read-only toolkit for looking inside a Windows computer: what is running, what persists, what changed, and which of it looks like an attacker. It changes nothing on the machine and sends nothing anywhere.

  1. Extract the whole archiveKeep the folder structure. Optionally compare the files with SHA256SUMS.txt.
  2. Open PowerShell as administratorStart, type PowerShell, choose Run as administrator. Without it the tool still runs, with less to see.
  3. Start the menuChange to the extracted folder and run the launcher. Everything else is a key press away.
PS C:\> cd "$HOME\Downloads\WinForensicX-3.2.0"
PS …\WinForensicX-3.2.0> .\Start-WinForensicX.ps1

If PowerShell refuses to run it

The message saysDo this
running scripts is disabledRun Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass, then start it again. It applies to this window only and ends when you close it.
is not digitally signedThe files still carry the downloaded-from-the-Internet mark. After checking the hashes, run Get-ChildItem -Recurse | Unblock-File in the folder, or use the command above.
A window flashes and closesThat is Explorer's right-click Run with PowerShell. It asks to change the execution policy with No as the default, never runs as administrator, and closes on any refusal. Start from a PowerShell window instead.

Find your way

Every task in this guide is labelled with the keys that reach it, like 2›1›1: Explore, Recent changes, Everything that changed. B goes back one level and Q quits from anywhere.

KeyMenuUse it to
1InvestigateRun a quick or full triage of this computer, collect evidence only, triage remote computers over WinRM, analyze exported .evtx logs, re-analyze a saved case, or analyze a folder of evidence collected from another system. Produces the HTML report.
2ExploreBrowse 57 live views in nine groups, from Recent changes and Evidence of execution to Security posture. Suspicious rows are flagged. A exports every view into one hashed inventory report.

Inside any view: S shows suspicious rows only, F filters by text, L lists every column, G opens the view as a sortable page in your browser, E saves it as CSV and R refreshes it.

Read the flags

Views that can show attacker activity check every row against the same rules the triage report uses. A flagged row gets four extra columns.

ColumnMeaning
FlagThe highest severity among the rules the row matched.
WhyEach reason in plain words, separated by |. The console shows the first reason and how many more there are.
TechniqueMITRE ATT&CK technique IDs for the reasons.
RuleThe triage rule ID, for the allowlist. Shown in the browser page and the CSV.
FlagWhat it usually meansWhat to do
CRITICAL HIGHA pattern attackers use and normal software rarely does: an encoded PowerShell launch, a known credential-theft tool, a deleted event log, a disguised double extension.Stop and look now. Note the time, keep the evidence, check what happened around it.
MEDIUMSuspicious in context: remote-access software, a new local account, a program running from AppData, an exposed port.Confirm with the owner of the machine whether it is expected.
LOWWorth a glance: a Windows binary that can proxy execution, an executable in Downloads, a static hosts entry.Review if it fits the timeline you are building.

Some findings are about many rows at once. A burst of 300 deletions or renames in ten minutes appears above the table as a pattern, because no single row shows it.

A flag is a lead, not a verdict. The opposite also holds: a view with no flags does not mean the computer is clean, only that nothing visible in that view matched a rule. The Notes under each view say what could not be seen, for example without administrator rights.

Silence a known-good flag

Copy the Rule value from the browser page or CSV into an allowlist file, give the reason, and load it with 6›4. Triage and the views then suppress it; the report still lists suppressed findings with your reason.

[
  { "Id": "NET-LISTENER-EXPOSED", "Entity": "listen:8080:java*", "Host": "BUILD-*",
    "Reason": "Build servers run Jenkins on 8080 (CHG-1042)" }
]

Flags raised by view-specific checks, such as a cleared Security log or a hosts-file override, have no rule ID and are always shown.

Investigations

Ten situations investigators and CTF players meet most, each with the keys to press and what to look at first. The sample output is synthetic, produced by this version of the tool from planted test data.

Is this PC compromised? 1›1

A user reports odd behaviour, an alert fired, or you are asked to clear a machine.

  1. Run a quick triage. It collects processes, network, autostarts, recent events and security posture, and takes one to five minutes.
  2. Open the report with 4›1. Start with the verdict and the start here list, then the findings grouped by category.
  3. Read the gaps section before you conclude anything. No process auditing and no Sysmon means much was simply not visible.

For evidence work, set the output folder to external media first with 6›1. Choose 1›2 for a full triage that also looks for web shells, dropped files, ransomware notes and exposed secrets.

Then: open the Recent changes timeline for the hours around the first finding.

Something was deleted 2›1›4

A file or folder is missing, or you suspect someone cleaned up after themselves.

  1. Deleted files reads the Recycle Bin of every fixed drive: original path, deletion time, owner, size, and whether the content is still recoverable, with its exact location. With Sysmon installed it adds deletions logged by events 23 and 26.
  2. File system changes 2›1›3 reads the NTFS change journal and needs administrator rights. It shows files created, deleted, overwritten, renamed and moved, and recognises a move into the Recycle Bin as a deletion with its original path.
  3. Watch for flags on deleted event logs, deleted PowerShell history, short-lived executables and bursts of deletions.

The change journal keeps a limited history, often hours to a few days on a busy system drive. The view tells you where its readable window starts.

Then: copy a recoverable item out of the $Recycle.Bin path shown, and hash it with 3›3.

A suspicious file or command 3›3

An attachment, a download, a binary in AppData, or a long Base64 command line in a log.

File triage reports hashes, the real file type against its extension, entropy, the download URL from the Mark of the Web, alternate data streams, the signature, PE facts and printable strings with any IOCs in them. The file is only read, never run. 3›4 does the same for a whole folder as one table.

For a command line, 3›5 peels -EncodedCommand, Base64, gzip and nested FromBase64String layers and shows each step. Nothing is executed.

PS> ConvertFrom-WfxEncodedCommand 'powershell -enc VwByAGkAdABlAC0ATwB1AHQAcAB1AHQAIAAnAGgAaQAnAA=='

Then: search for the hashes and indicators you found across the computer with 3›1.

Malware lab and CTF 3›6

You will run a sample, or solve a forensics challenge, and need to know exactly what it changed.

  1. Before the run, take a file-integrity baseline of the folders that matter, and collect evidence with 1›3.
  2. Optionally start the 5 live monitor, which reports new suspicious processes and connections as they appear.
  3. After the run, compare the files with 3›7: added, deleted, content changed, or only timestamps changed. Collect again and compare the two cases with 4›5 for new processes, autostarts, services, listeners and DNS names.
PS> New-WfxFileBaseline -Path C:\Users\lab\AppData, C:\ProgramData -OutputPath E:\bl\before.json
PS> Compare-WfxFileBaseline -Baseline E:\bl\before.json | Where-Object Change -ne 'TimestampOnly'

Then: the Recent changes views show the registry, task and service side of the same run.

Sweep for known IOCs 3›1

You have hashes, IP addresses, domains or strings from a report or another host.

The hunt matches MD5, SHA-1 and SHA-256 hashes, exact IP addresses, domains with their subdomains, and strings against what it collects from the computer, event logs included. -FileScan also hashes files, and -HashProcesses hashes running programs. A text file with one indicator per line works as well as a typed list. 3›2 sweeps a saved case instead, without touching the live system.

PS> Invoke-WfxHunt -IocFile .\iocs.txt -FileScan
PS> Invoke-WfxTriage -ComputerName srv01,srv02 -Credential (Get-Credential)

Then: for several machines, collect from each over WinRM with 1›4 and hunt in the saved cases.

Did this program ever run? 2›2›1

A tool was used and deleted, or you need to prove a program ran, when and as whom.

Programs that ran or existed merges every execution artifact Windows keeps: Amcache (with the program's SHA-1, publisher and first-seen time), ShimCache, Prefetch, BAM, UserAssist and, on Windows 11, the Program Compatibility Assistant. One program usually appears in several of them; the triage report joins them into one finding per file and lists where it was seen. These records stay after the program is deleted.

Flags point at attack and exfiltration tools (Mimikatz, PsExec, Rclone, MEGAsync...), programs in staging folders such as Temp, Users\Public or the root of ProgramData, and Windows program names in the wrong folder.

PS> Get-WfxArtifact -Artifact Amcache, Prefetch, ShimCache -Flag | Where-Object Flag | Format-Table Flag, Why, Path, Time
PS> Get-WfxArtifact -Artifact Amcache | Where-Object Sha1 -eq 'sha1 from a threat report'

Live Amcache is locked by Windows; the view says so. Copy C:\Windows\appcompat\Programs\Amcache.hve with a raw-copy tool (KAPE, FTK Imager) and parse the copy.

Then: Folders and files users opened 2›2›2 shows what the same user browsed and opened around that time, including USB drives and network shares.

Evidence from another computer (KAPE, image, CTF) 1›7

You have files, not the machine: a KAPE or Velociraptor collection, a mounted disk image, or the evidence folder of a forensics challenge.

Point the triage at the folder. Files are recognised by content, so renamed hives still work: SYSTEM (ShimCache, BAM, computer name), SOFTWARE (Windows version), Amcache.hve, NTUSER.DAT (UserAssist, RunMRU, typed paths, Explorer searches, ShellBags), UsrClass.dat (ShellBags), Jump Lists, .lnk files, Chromium History and Firefox places.sqlite, Prefetch, PCA and Defender logs, and every .evtx file. You get the same report as a live triage, with incidents, the attack path and an Execution section.

PS> Invoke-WfxTriage -ArtifactPath D:\kape\C -CaseName ctf-01
PS> Invoke-WfxHunt -IocFile .\iocs.txt -ArtifactPath D:\kape\C

Hives copied from a running system are often "dirty". Copy each hive's .LOG1 and .LOG2 with it: the tool replays them in memory, and says so when it cannot. Nothing in the folder is changed.

Then: run your Sigma rules over the event logs in the same folder with -SigmaPath, or scan the folder with your YARA rules with -YaraRules.

Many computers: where did it start? 4›7

More than one host is involved and you need patient zero, the spread, and what the hosts have in common.

  1. Triage every host into the same folder: locally on each, or over WinRM with 1›4.
  2. Build the fleet report. It ranks hosts by risk, orders them by their first attacker activity, lists indicators and findings that appear on two or more hosts, and shows the ATT&CK stages seen on each.
  3. Export what other teams need with 4›6: a Timesketch CSV for the timeline, ECS JSON lines for Elastic, Splunk or Sentinel, and a STIX 2.1 bundle of indicators for MISP or OpenCTI. Exports go next to the case, so the hashed case folder is not changed.
PS> New-WfxFleetReport -Path E:\ir-cases
PS> Export-WfxCase -InputPath E:\ir-cases\WFX_PC-0412_20261107-140211Z -Format Stix, Ecs

Hand the case over 4›3

The work goes to a colleague, a lawyer, or a write-up.

  1. Verify the case: every file is re-hashed against manifest.json, and any changed, missing or added file is reported.
  2. Record the manifest's SHA-256, printed at the end of each run, somewhere outside the case folder. The manifest is not signed, so that recorded hash is what makes later tampering detectable.
  3. Export one UTC-sorted timeline with 4›4 for a spreadsheet or timeline tool.
PS> Test-WfxCase -Path E:\cases\WFX_PC-0412_20261107-140211Z
PS> Export-WfxTimeline -InputPath E:\cases\WFX_PC-0412_20261107-140211Z -Format Csv

Limits and safety

What it will and will not do

  • Read-only: it changes no settings and executes nothing it finds. It sends no network traffic of its own (remote mode uses WinRM you initiate; -ExposureScan reads the domain SYSVOL share).
  • Its only writes are its own case folder (default Desktop\WinForensicX) — use -OutputPath on external media for evidence work. Reading files can update NTFS last-access times.
  • PowerShell 7 itself (not WinForensicX) sends anonymous start-up telemetry to Microsoft unless POWERSHELL_TELEMETRY_OPTOUT=1 is set; set it for evidence work, or use Windows PowerShell 5.1, which does not.
  • Credential exposure is AUDITED, never extracted: it reports THAT a secret is exposed with the value redacted to type + length.
  • No LSASS dumping, no SAM/NTDS hash parsing, no DPAPI/browser decryption, no exfiltration.
  • Command lines, event messages and file contents are secret-scrubbed at collection time, so the raw bundle is safe to keep and ship.

What to keep in mind

  • Findings are LEADS for an analyst, not verdicts. A finding means "look here," not "this host is compromised."
  • Read findings alongside the collection gaps: with no process auditing and no Sysmon, "nothing found" mostly means "nothing could be seen" - the report says so.
  • It is a TRIAGE tool, not a forensic imager. It does not acquire disk/memory images or carve deleted files.
  • Detections are heuristic: expect some false positives and false negatives. Tune with custom rule packs ($env:WFX_RULES) and an allowlist (-AllowlistPath / $env:WFX_ALLOWLIST).
  • Two scores: Compromise risk (evidence of attacker activity) and Posture (hardening/visibility gaps). A clean but un-hardened host scores low risk, high posture.
  • Only loaded user registry hives (logged-on users) are inspected; event collection is capped per query and caps are reported as gaps.
  • Administrator rights are recommended; without them some data is unavailable (recorded as gaps). Remote mode needs WinRM enabled on the target.
  • It will not extract, decrypt, or dump secrets - that is a deliberate boundary, not a missing feature.
  • The manifest is not signed: record its SHA-256 (printed at the end of each run) out-of-band to make the case tamper-evident.
  • Artifacts: Amcache.hve is locked on a running system (collect it with a raw-copy tool and use -ArtifactPath); dirty hives are repaired from .LOG1/.LOG2 only when the logs continue the hive; browser rows still in the -wal file and compressed Prefetch contents are not read (Prefetch gives name and times); SRUDB.dat is usually locked live (collect it); $MFT is read from collected files only, and deleted SRUM records are skipped.
  • Sigma: rules run only on the event logs and IDs the tool collects (rules can add Security/System IDs they need); aggregations and correlation rules are skipped and counted as a gap. YARA needs a yara executable you provide.

Requirements

  • Windows PowerShell 5.1 or PowerShell 7+. No external modules. Live collection needs Windows; analysis, re-analysis, hunting in saved cases, timelines, diffs and file triage also run on Linux/macOS (PowerShell 7).
